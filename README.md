# ChromeFinder — Android-приложение для поиска информации в Google Chrome

Приложение для Android, которое **управляет настоящим Google Chrome**: открывает
нужный сайт, дожидается загрузки страницы, находит на ней заданную информацию
(по ключевому слову / правилу) и **показывает результат на экране** приложения.

> Управление другим приложением (Chrome) на Android без root делается через
> **Accessibility Service** — это официальный системный API. Пользователь сам
> включает службу в настройках телефона. Никакого взлома или обхода защиты —
> только чтение содержимого экрана и имитация нажатий, как это делают
> программы экранного доступа.

---

## Что приложение умеет (целевой сценарий)

1. Пользователь в приложении вводит:
   - **URL** нужного сайта;
   - **что искать** (ключевое слово / фраза / шаблон).
2. Нажимает «Запустить».
3. Приложение открывает этот адрес в **настоящем Chrome** (через Intent).
4. Accessibility Service:
   - определяет, что активен Chrome;
   - дожидается окончания загрузки страницы;
   - обходит дерево элементов страницы и собирает текст;
   - ищет совпадения с запросом и вырезает нужный фрагмент.
5. Результат возвращается в приложение и **показывается на экране** (список
   найденных фрагментов + кнопка «Открыть в Chrome»).

## Архитектура

```
┌──────────────────────────────────────────────────────────────┐
│                        Приложение                             │
│                                                                │
│  MainActivity (UI)                                             │
│   ├─ поле URL                                                  │
│   ├─ поле «что искать»                                         │
│   ├─ кнопка «Запустить»                                        │
│   └─ список результатов                                        │
│            │                         ▲                          │
│            │ сохраняет запрос         │ результаты              │
│            ▼                         │                          │
│  SearchRepository (общее состояние, SharedFlow/Prefs)         │
│            │                         ▲                          │
└────────────┼─────────────────────────┼──────────────────────────┘
             │ launch Chrome (Intent)   │ broadcast результата
             ▼                          │
   ┌──────────────────┐      ┌─────────────────────────────────┐
   │  Google Chrome    │◄────│  BrowserAutomationService        │
   │  (внешнее прилож.)│     │  (AccessibilityService)          │
   │                   │────►│   ├─ ловит события Chrome         │
   │   страница сайта  │     │   ├─ ждёт загрузку                │
   │                   │     │   ├─ обходит AccessibilityNodeInfo│
   │                   │     │   └─ ищет совпадения              │
   └──────────────────┘      └─────────────────────────────────┘
```

### Ключевые компоненты

| Компонент | Назначение |
|-----------|-----------|
| `MainActivity` | Ввод URL + запроса, отображение результатов |
| `SearchRepository` | Хранит текущий запрос и отдаёт результаты (StateFlow) |
| `BrowserAutomationService` | AccessibilityService: следит за Chrome, читает страницу |
| `PageScanner` | Обход дерева `AccessibilityNodeInfo`, сбор и поиск текста |
| `ChromeLauncher` | Открывает URL в Chrome через `Intent` |
| `Result`/`SearchQuery` | Модели данных |

## Технологии

- **Язык:** Kotlin
- **UI:** Jetpack Compose (или XML View — решим на старте)
- **Мин. версия Android:** API 26 (Android 8.0)
- **Сборка:** Gradle (Kotlin DSL)
- **Ключевые API:** `AccessibilityService`, `AccessibilityNodeInfo`, `Intent`

---

## Ограничения и честные оговорки

- **Accessibility Service включает пользователь вручную** (Настройки →
  Спец. возможности). Это требование Android, обойти нельзя.
- Chrome не отдаёт «чистый HTML» — служба видит только то, что отрисовано на
  экране (видимый текст). Длинные страницы возможно потребуется
  **прокручивать**, чтобы прочитать всё.
- Google ограничивает публикацию приложений с Accessibility Service в Play
  Store. Для личного использования (sideload APK) ограничений нет.
- Сборку/запуск проверяем на **реальном устройстве или эмуляторе** — в
  облачном контейнере полноценного Android-окружения может не быть, поэтому
  упор на корректный код, который собирается локально.
